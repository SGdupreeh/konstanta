# Регламент аудита доступности (a11y / WCAG 2.2 AA)

## 1. Проверка клавиатурной навигации
1. **Порядок табуляции (`tabindex`):**
   - Навигация клавишей `Tab` должна идти строго в логическом порядке чтения документа (слева направо, сверху вниз).
   - Запрещено использование положительных значений `tabindex="1"`, `tabindex="2"` (только `0` или `-1`).
2. **Фокус-ловушка (Focus Trap):**
   - При открытии модального окна (`role="dialog"` или `<dialog>`) фокус обязан переместиться внутрь окна (на первый интерактивный элемент или крестик закрытия).
   - Клавиша `Tab` не должна уходить за пределы модального окна на фоновые элементы страницы.
   - Нажатие `Escape` обязано закрывать модальное окно и возвращать фокус на кнопку, которая его открыла.
3. **Видимость фокуса:**
   - Ни в коем случае не использовать `outline: none;` без создания альтернативного видимого стиля `:focus-visible` с контрастом не менее 3:1 к фону.

## 2. Семантика и вспомогательные технологии (Screen Readers)
1. **Заголовки (`<h1>`–`<h6>`):**
   - На каждой странице должен быть ровно один заголовок первого уровня `<h1>`.
   - Нельзя перескакивать через уровни (например, от `<h2>` сразу к `<h4>`).
2. **Ориентиры (Landmarks):**
   - Наличие ключевых тегов: `<header>`, `<nav>`, `<main>`, `<footer>`, `<aside>`, `<section>` (с `aria-labelledby`).
3. **Изображения (`alt`):**
   - Информативные изображения (фотографии объектов, схемы) обязаны содержать содержательное описание в `alt`.
   - Чисто декоративные иконки должны содержать пустой атрибут `alt=""` либо `aria-hidden="true"`.
4. **Кнопки без текста (иконки):**
   - Кнопки, содержащие только SVG-иконку (закрыть, бургер, стрелка слайдера), обязаны иметь атрибут `aria-label="Описание действия"`.

## 3. Цветовой контраст
- Обычный текст (< 18pt или < 14pt bold): коэффициент контраста к фону не менее **4.5:1**.
- Крупный текст (>= 18pt или >= 14pt bold): коэффициент контраста не менее **3.0:1**.
- Графические элементы интерфейса (границы инпутов, иконки кнопок): не менее **3.0:1**.

## 4. Формат отчета об аудите
Отчет оформляется в виде артефакта `a11y-audit-report.md`:
- Таблица найденных нарушений (Файл, Строка, Элемент, Тип нарушения по WCAG).
- Точный код исправления (Before / After).
- Итоговый статус (Pass / Fail).
