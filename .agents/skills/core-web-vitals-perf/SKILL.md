# Регламент оптимизации Core Web Vitals

## 1. Largest Contentful Paint (LCP < 2.5s)
1. **Предзагрузка критического контента:**
   - Если на первом экране есть главный фоновый баннер или логотип, добавить `<link rel="preload" as="image" href="..." fetchpriority="high">`.
2. **Шрифты:**
   - Подключение через `font-display: swap;`.
   - Использование подмножеств шрифта (только кириллица + латиница + цифры) в формате WOFF2.
3. **Критический CSS:**
   - Минимизировать объем CSS, блокирующего рендеринг. Базовые стили первого экрана должны загружаться мгновенно.

## 2. Cumulative Layout Shift (CLS < 0.1)
1. **Резервирование места:**
   - Всем картинкам, баннерам, видео и iframe задавать фиксированные соотношения сторон (`aspect-ratio: 16/9;` или `width` и `height`).
2. **Динамический контент:**
   - Не вставлять динамические плашки (баннеры, уведомления) над уже отрендеренным контентом, чтобы не сдвигать страницу вниз.

## 3. Interaction to Next Paint (INP < 200ms)
1. **Освобождение главного потока (Main Thread):**
   - Не вешать тяжелые синхронные вычисления на события `scroll`, `resize` или `input`.
   - Обязательно использовать троттлинг (`throttle`) или дебаунс (`debounce`) для событий ввода и прокрутки.
   - Использовать `requestAnimationFrame` для анимаций, управляемых JavaScript.
