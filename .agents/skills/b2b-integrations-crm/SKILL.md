# Регламент надежной интеграции лид-форм (CRM & Webhooks)

## 1. Защита от потери лидов (Fail-Safe Submissions)
1. **Превентивное сохранение черновика (Draft Auto-Save):**
   - При вводе данных в форму сохранять поля в `localStorage` (с ключом вроде `draft_lead_form`).
   - При случайном обновлении страницы или разрыве связи восстанавливать значения.
   - Очищать `localStorage` только после подтверждения успешной отправки на сервер (HTTP 200).
2. **Защита от дабл-клика (Double Submit Prevention):**
   - В момент клика «Отправить» кнопка переводится в состояние `:disabled` и получает класс `.is-loading`.
   - Текст кнопки меняется на «Отправка...».
   - Кнопка разблокируется только по завершении сетевого запроса.
3. **Логика повторных попыток (Retry Policy):**
   - При сетевой ошибке (Network Error / Timeout) повторять запрос до 3 раз с экспоненциальной задержкой (1s, 2s, 4s).
   - Если отправка не удалась — показывать вежливое сообщение с прямым номером телефона/WhatsApp и сохранять заявку в локальную очередь на повторную отправку при появлении сети.

## 2. Стандартизированный Payload (Схема данных лида)
Каждый отправляемый вебхук обязан содержать единый структурированный JSON:
```json
{
  "client_name": "Иван Петров",
  "phone": "+7 (999) 000-00-00",
  "email": "ivan@example.ru",
  "source": {
    "page_url": "https://company.ru/schools.html",
    "form_id": "modal_school_quote",
    "utm_source": "yandex_direct",
    "utm_medium": "cpc",
    "utm_campaign": "b2b_schools",
    "referrer": "https://yandex.ru"
  },
  "timestamp": "2026-09-23T08:00:00Z"
}
```
